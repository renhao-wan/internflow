# 实习日志规则（回归样例，虚构）

> 本文件是回归测试用的虚构规则，不是真实用户数据，不得替换为真实实习内容。

## 为什么写

实习结束时能拿出简历条目、面试案例和一份能力清单。判断日志有没有用：三天后能还原当天、月底能提炼、留下现象和证据。不写感想和情绪。

## 三层结构

原料是当月日志，月结是「本月小结」，成品是 `素材库.md`。简历和面试只从素材库取。

## 目录约定

`<入职年月>-<公司名>-<岗位>/`：按月日志 `YYYY-MM.md`、`素材库.md`、`主题笔记/`，需要时 `架构图/`。技术细节单独建主题笔记，不建空文件。

## 每天写什么

五块：今日做了什么、卡住的问题、学到什么、待问、明天。前两块必写，后三块没内容写「无」。新记录插在 `## 本月小结` 之后、已有记录之前，标题 `### YYYY-MM-DD（周X，第 N 天）`。

1. 今日做了什么：到模块、接口、表这一级
2. 卡住的问题：现象 → 排查 → 根因 → 解决
3. 学到什么：只写真正搞懂的点
4. 待问：每条标主归属
5. 明天：最多 3 条，包含明确承诺的事

## 待问怎么收口

分挡路和记着就行两类。每周清一次；月底没勾掉的进本月小结「未解决」，最多留五条。用户说不管了就直接删，不追问。

## 业务理解怎么记

有更新时加 `**业务理解（第 N 版，待验证）**`，写角色、核心用例、完整链路、不确定点、权限约束。旧版本不删，未验证标「待验证」。

## 代码和架构图怎么记

代码不存原文，只记类名/方法名和改前改后逻辑，字段名、表名、常量通用化。架构图只画自己负责的调用链和数据流，放 `架构图/`，日志里用 `![[图名]]` 嵌入。

## 和 AI 协作的约定

一次只问一个问题，写日志控制在 7-9 轮；答不上来写「未知」进待问；写完先确认；不自动 git commit；不编数字和结果。

## 保密

可以写仓库名、系统名。不写密码、token、客户姓名、未公开数据、内网地址与域名、连接串、代码原文。

## 月结与素材库

月底在当月日志开头（H1 和引用说明之后）写 `## 本月小结`，写五项：主要模块、解决的问题、新掌握、候选案例（1-2 件，标日期）、未解决（最多五条）。再从候选案例挑 1-2 条进素材库，六项字段：标题、背景、问题、我做了什么、结果、可能追问；写不满不进。
