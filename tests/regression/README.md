# 回归样例

用于人工验证六个 skill 的行为是否仍符合设计。所有内容均为虚构，不含真实公司、人员、代码或数据。

## 用法

1. 建一个临时项目根目录，例如 `<tmp>/internflow-regression`。
2. 把 `fixtures/` 里的内容复制进去。
3. 建 `<tmp>/internflow-regression/.claude/internflow.local.md`：

   ```markdown
   ---
   rules: "<tmp>/internflow-regression/规则.md"
   log_root: "<tmp>/internflow-regression"
   ---

   # internflow 工作区配置
   ```

4. 在该目录启动 `claude --plugin-dir "/path/to/internflow"`，按下面的场景运行。

## 固定数据

- 月份 `2026-10` 已结束，日志最后一条是 `2026-10-30`。
- `[[缓存穿透处理]]` 指向真实存在的主题笔记，`[[不存在的笔记]]` 是悬空链接。
- `2026-10-29` 的「明天」有 4 条，超过规则给的条数上限。
- `2026-10-30` 没有逐条回应 `2026-10-29` 的「明天」。
- `2026-10-29` 有一条待问没标归属。
- `2026-10-29` 标「第 2 天」，但文件里没有第 1 天的记录。
- 文件里没有「## 本月小结」。
- 素材库有一条完整案例，和一条缺「可能追问」的案例。

## 场景

### R1 写日志

运行 `/internflow:internship-log`，用虚构内容描述 `2026-11-02`。

检查：

- 开场先读出 `2026-10-30` 的「待问」和「明天」，逐条核对
- 一次只问一个问题，轮数由规则第 8 节控制
- 五块齐全，无内容的块写「无」
- 技术细节外置到 `主题笔记/`，链接指向真实文件
- 写完展示当天这一节，不自动 commit

### R2 审核（整月）

运行 `/internflow:internship-log-review 2026-10`。

检查：

- 悬空链接被报出，带行号和规则依据
- `2026-10-29` 的「明天」超条数被报出
- `2026-10-30` 未回应前一天的「明天」被报出
- 未标归属的待问被报出
- 该月已结束但没有「## 本月小结」被列为必须改
- 输出四段齐全，「已通过」不为空，跳过项注明原因

### R3 月结

运行 `/internflow:internship-log-monthly`。

检查：

- 本月小结五项齐全，数字都有出处
- 未解决按规则控制数量，旧月份待问不往后传
- 素材库只补合格案例，缺字段的案例不新增
- 已有小结时先展示、说明覆盖、等确认
- 不自动 commit

### R4 改规则

运行 `/internflow:internship-log-rule-maintain`，把「保密」和「月结与素材库」调换顺序。

检查：

- 规则文件章节顺序更新
- 四个执行 skill 的「按规则第 X 节」全部更新
- 插件根 README 的规则章节表更新
- `node ${CLAUDE_PLUGIN_ROOT}/scripts/check.mjs` 通过

### R5 工作区配置

- 首次运行前没有 `.claude/`：skill 只读配置，不创建目录
- 路径没问齐或中途放弃：不留下 `.claude/`
- 给一个不存在的路径：不写入配置，报错重问，仍不创建目录
- 破坏 `.claude/internflow.local.md` 的 frontmatter 或 YAML：按无配置处理，覆盖前告知
- 只给 `rules` 不给 `log_root`：不写入部分配置，继续问缺失字段，问齐后一次写入
- `rule-maintain` 在无配置时只问规则路径，不创建配置文件
- 写入后确认项目 `.gitignore` 的 `.claude/*.local.md` 规则能挡住该文件

### R6 实习总结

先跑完 R3，让当月日志里有「本月小结」和「未解决」，再运行 `/internflow:internship-log-retro`。

检查：

- 未确认实习已结束时先提醒总结会不完整，不直接开始生成
- 读全部月结，把「未解决」汇总成一张清单并标来源月份，不改原日志
- 逐条请用户确认已解决 / 仍开放 / 放弃，不替用户判断，不原样照搬
- 简历素材和面试提纲只从素材库取，不从日志临时提炼
- 简历素材覆盖素材库全部合格案例，没有按条数或行数删减
- 能力清单每条都有「之前不会、现在会」的事实支撑
- 默认写到实习目录下的 `实习总结.md`，开头有来源说明和「以总结为准」
- 不回写月结里的「未解决」
- 没有月结或素材库时按缺失情况询问，不硬造
- 目标文件已存在时先展示、说明覆盖、等确认
- 不自动 commit

## 提交限制

这些样例可以提交；真实用户数据仍然由 `.gitignore` 的防护规则挡住。
