# 实习目录初始化

单文件执行手册。**只创建目录和模板文件；不写日志正文、不审日志、不月结。**

## 第一步：读取工作区

按插件根目录的 `references/workspace.md`（`${CLAUDE_PLUGIN_ROOT}/references/workspace.md`）读项目根目录的 `.claude/internflow.local.md`，取 `log_root` 作为默认值。

- 有 `log_root`：作为默认，用户本次给的路径优先
- 没有配置或路径失效：逐项询问，不要猜、不要用默认路径

## 第二步：收集目录信息

一次只问一个问题：

1. **日志根目录**：已有配置时展示默认值，用户可直接确认；根目录不存在时，问「新建这个目录，还是换一个路径」，用户确认新建才创建，不自动创建没确认的路径
2. **入职年月**：`YYYY-MM`，如 `2026-10`
3. **公司名**
4. **岗位**：如 `Java实习`

目录名 = `<入职年月>-<公司名>-<岗位>`。

校验：

- 年月必须是 `YYYY-MM`，非法就重问
- 公司名、岗位先 `trim`，`trim` 后为空就重问
- 目录名不能包含路径分隔符 `/\`、`..`、控制字符
- Windows 下不能包含 `<>:"|?*`
- 校验不通过就重问，不自动修正、不猜

## 第三步：检查已有内容

- 目录不存在：新建
- 目录已存在：不覆盖，逐项检查缺失文件
- 文件已存在：跳过，在报告里写「已存在」

不删除、不改写任何已有文件。

## 第四步：展示计划

```text
将创建：
  <日志根目录>/2026-10-示例科技-Java实习/
    2026-10.md
    素材库.md
    主题笔记/

已存在，将跳过：
  （无）

确认吗？
```

用户确认后执行。用户要改年月、公司或岗位时，回到第二步重问，不直接改目录名。

## 第五步：创建

| 路径 | 来源 |
|---|---|
| `<入职年月>-<公司名>-<岗位>/` | 新建 |
| `<入职年月>.md` | `${CLAUDE_PLUGIN_ROOT}/templates/日志.template.md`：只把 H1 的 `YYYY-MM` 换成实际年月；删除 `### YYYY-MM-DD` 示例记录及其下所有块；保留 H1、引用说明和 `## 本月小结` |
| `素材库.md` | `${CLAUDE_PLUGIN_ROOT}/templates/素材库.template.md`，原样复制 |
| `主题笔记/` | 新建空目录 |

不创建：

- `架构图/`：需要时再建
- `实习总结.md`：实习结束时由 `retro` 生成
- 任何日期记录：日志正文由 `log` 写
- 模板里的日期示例标题和空块：一并删除，不留 `YYYY-MM-DD`

## 第六步：处理配置

先完成第五步的目录和文件创建，成功后再写配置；顺序颠倒会违反 `workspace.md` 的「首次保存时 `log_root` 必须已存在」。

- 配置里已有 `rules` 和 `log_root`：只补 `log_root`（如果本次改了），不重复询问规则
- 配置里只有 `log_root` 或没有配置：不写半套配置；完成后提示「规则文件还没定，运行 `/internflow:rule-init`」
- 用户本次给了规则路径且校验通过：按 workspace.md 写入完整配置
- 不创建规则文件

## 第七步：报告

```text
初始化完成
  目录：2026-10-示例科技-Java实习/
  创建：2026-10.md、素材库.md、主题笔记/
  跳过：（无）

下一步：
  - 还没有规则文件：/internflow:rule-init
    运行后日志根目录填：<本次的日志根目录>
  - 已经定好规则：/internflow:log
```

## 交付前检查

- 目录名符合 `<入职年月>-<公司名>-<岗位>`
- 日志文件的 H1 是 `<年月> 实习日志`，没有 `YYYY-MM-DD` 坏标题
- 没有保留模板里的日期示例记录和空块
- 没有覆盖任何已有文件
- 没有创建 `架构图/`、`实习总结.md`、日期记录
- 配置没有写半套
- 不自动 `git commit`

## 禁止

- 不写日志正文
- 不审日志、不月结、不总结
- 不创建规则文件
- 不覆盖已有文件
- 不删除任何文件
- 不自动 `git commit`
